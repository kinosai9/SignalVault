**Date**: 2026-07-31

## 验证目标

验证 M3-B2 Phase 4 发现的 Windows Runtime DLL 问题是否为开发环境污染。

## 验证方法

由于无 Windows Sandbox 且非管理员权限，采用以下替代验证方案：

1. **系统 Python 隔离测试** — 验证 DLL 文件级别的兼容性
2. **嵌入式 Python + 系统 Python 混合测试** — 验证代码 + 包的兼容性
3. **Briefcase stub 不同目录布局测试** — 验证 stub 路径解析

## 关键发现

### 发现 1: `_ctypes.pyd` 版本差异 (环境问题 — 确认)

| 文件 | 嵌入式 Python 3.14.4 | 系统 Python 3.14.0 | MD5 相同? |
|------|---------------------|-------------------|-----------|
| `_ctypes.pyd` | 142,680 bytes | 141,656 bytes | **NO** (`409E...` vs `5860...`) |
| `libffi-8.dll` | 39,696 bytes | 39,696 bytes | **YES** |

`_ctypes.pyd` 的 MD5 哈希不同，确认 Python 3.14.0 与 3.14.4 之间存在 ABI 级别的二进制差异。

**影响**: 当系统 Python 在当前目录有嵌入式 `_ctypes.pyd` 时，Python import 系统优先加载当前目录的 `.pyd` 文件（当前目录在 `sys.path` 中），导致加载了嵌入式 3.14.4 的 `_ctypes.pyd` 配合系统 3.14.0 的 `python314.dll`，版本不匹配崩溃。

**验证**: 嵌入式 `_ctypes.pyd` 单独在目录中 → 系统 Python `import ctypes` 立即失败。

### 发现 2: 系统 Python + 已安装 App 代码 → 完美运行

```
系统 Python 3.14.0 + 已安装 MSI 的 app/ 和 app_packages/
→ launch() 成功
→ Health check: signalvault v0.1.0, status: ok, db: ok
→ 浏览器自动打开
→ 所有日志正常
```

**这证明**:
- 嵌入的 Python 包 (`app_packages/`) 与 Python 3.14.0 **二进制兼容**
- SignalVault 代码在 Windows 上**功能完整**
- 路径解析 (`AppPaths`) 正确 → `%APPDATA%/SignalVault/` 正常创建
- SQLite 读写正常
- Web 服务正常启动

### 发现 3: Briefcase GUI Stub 间歇性失败

- Stub 从 build 目录运行: 有时成功（10:34 日志有 Python 输出），有时失败（退出码 1，无日志）
- Stub 从 temp 目录运行: 同上，行为不一致
- Stub 从安装目录运行: 同上
- **失败时**: 退出码 1，Python 日志完全为空 → Python 解释器初始化阶段失败

**可能原因**:
1. Briefcase GUI-Stub-3.14-amd64-b11 与 Python 3.14.4 存在兼容性问题
2. Windows DLL 搜索路径在特定条件下干扰 stub 初始化
3. Briefcase 0.4.4 + Python 3.14.4 的已知问题

## 结论

### M3-B2 原结论修正

| 原结论 | 修正后 |
|--------|--------|
| DLL 冲突是代码问题 | **不是**。代码完美兼容 Windows |
| Runtime 不可用 | **可用**。系统 Python + 已安装包正常运行 |
| 评级 B | **维持 B**，但原因不同：App 代码可用，Stub 需修复 |

### 真正的阻断项

**唯一阻断项**: Briefcase GUI stub 二进制 (`GUI-Stub-3.14-amd64-b11.zip`) 在 Python 3.14.4 环境下初始化不稳定。

**App 代码状态**: Windows 就绪。通过系统 Python 可以直接运行。

### 建议

1. **短期 workaround**: 在 Windows 上通过系统 Python 运行：
   ```powershell
   $env:PYTHONPATH = "$env:LOCALAPPDATA\Programs\Kinosai\SignalVault\app;$env:LOCALAPPDATA\Programs\Kinosai\SignalVault\app_packages"
   python -c "from signalvault.launcher import launch; launch()"
   ```

2. **中期修复**: 向 BeeWare 报告 `GUI-Stub-3.14-amd64-b11` + Python 3.14.4 兼容性问题，或降级嵌入式 Python 至 3.14.0

3. **正式方案**: 考虑不使用 Briefcase GUI stub，改用自定义 Console 子系统启动器（可以看到错误输出，方便调试）
